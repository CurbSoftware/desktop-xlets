# Ports guide: GNOME and KDE

How the Cinnamon xlets are ported to GNOME Shell and KDE Plasma, and how
everything ships in one bundle AppImage. The Cinnamon originals and their
Spices pipeline are unchanged; this guide covers only the new trees.

## Model

Each Cinnamon xlet family has two sibling source trees, one per desktop:

| Family | GNOME tree (uuid) | KDE tree (package id) |
|---|---|---|
| world-clock | `gnome-world-clock@curbsoftware` | `kde-world-clock` (`com.curbsoftware.worldclock`) |
| color-clock | `gnome-color-clock@curbsoftware` | `kde-color-clock` (`com.curbsoftware.colorclock`) |
| workspace-grid | `gnome-workspace-grid@curbsoftware` | `kde-workspace-grid` (`com.curbsoftware.workspacegrid`) |
| workspace-names | `gnome-workspace-names@curbsoftware` | `kde-workspace-names` (`com.curbsoftware.workspacenames`) |
| command-launcher | `gnome-command-launcher@curbsoftware` | `kde-command-launcher` (`com.curbsoftware.commandlauncher`) |
| panel-profiles | `gnome-panel-profiles@curbsoftware` | `kde-panel-profiles` (`com.curbsoftware.panelprofiles`) |

Trees are separate codebases by decision, not accident. The Cinnamon side
duplicates shared JS across xlets because Cinnamon allows no cross-xlet
imports; the ports extend the same copy-and-diverge convention across
desktops. Pure logic is copied into each tree and guarded by per-tree
headless tests, never imported across trees.

Tooling: `python3 dev-tools/ports-release.py list | check | test | build`,
selection by alias (`world-clock`), alias plus desktop (`world-clock@gnome`),
uuid, package id, or source dir. Output lands in `dist/ports/`. The
`blocked` flag means a tree is not built yet and clears as phases land.

## GNOME (Shell 45+, ESM)

Tree layout:

```
gnome-<family>@curbsoftware/
  metadata.json     uuid, name, description, version, shell-version, url
  extension.js      export default class extends Extension
  prefs.js          export default class extends ExtensionPreferences
  widget.js         St/Clutter actor construction
  lib/              pure ESM modules (the only headless-testable JS)
  store.js          JSON settings, atomic writes
  defaults.js       defaults lifted from the Cinnamon settings schema
  stylesheet.css
```

Mechanisms:

- Desktop widgets: GNOME has no desklet API. The widget is an St.Bin
  added to `Main.layoutManager._backgroundGroup`, positioned from stored
  x/y per monitor, with a settings toggle to parent it to `Main.uiGroup`
  instead (always-visible fallback).
- Panel buttons: `PanelMenu.Button` plus `Main.panel.addToStatusArea()`.
- Workspaces: `global.workspace_manager` for state and signals. Names
  are the `workspace-names` strv in `org.gnome.desktop.wm.preferences`.
  Add/remove via `append_new_workspace` and `workspace.remove`. When
  `org.gnome.mutter dynamic-workspaces` is true, the grid shows tiles
  but disables add/remove with an inline explanation.
- Timezones: `GLib.DateTime` with `GLib.TimeZone.new(identifier)`.
- Settings: JSON at `~/.config/gnome-<family>@curbsoftware/settings.json`.
  Not gschema: the Cinnamon schemas are nested arrays that map badly to
  gsettings types, and gschema would push schema compilation onto the
  installer. Cost: settings are invisible to dconf dumps.
- prefs.js: libadwaita pages. The timezone chooser is a searchable
  Gtk.DropDown fed from `/usr/share/zoneinfo`.

## KDE (Plasma 6)

Tree layout:

```
kde-<family>/
  metadata.json                KPlugin fields, KPackageStructure Plasma/Applet
  contents/ui/main.qml         branches on Plasmoid.formFactor
  contents/ui/lib/tzdata.js    generated by dev-tools/gen-tz-table.py
  contents/ui/lib/tz.js        offset lookup, mirrors the Python reference
  contents/config/main.xml     KConfigXT keys
  contents/ui/config/config.qml
  tests/                       node-run pure JS tests
```

One package serves panel and desktop: `main.qml` branches on form factor
and the user drops the same plasmoid in either place.

Mechanisms:

- Timezones: Qt V4 has no GLib and no full ECMA-402. The build generates
  a transition table (default window 2020 to 2050) from the host
  zoneinfo database; lookups outside the window clamp to the nearest
  known offset, so rebuild once real time approaches the end. The
  generator dedupes zones with identical transitions into aliases.
- Workspaces: session bus `org.kde.KWin` `/VirtualDesktopManager` for
  desktops, names, rows, and change signals. kwinrc is only written for
  row count when dynamic virtual desktops are off.
- Command spawning: behind a `lib/launcher.js` seam because the
  executable dataengine is gone in Plasma 6; the launcher runs
  applications and .desktop entries through the standard URL
  mechanism instead, and the seam is the swap point if a helper lands.
- Layout capture (Plasma Layouts): QML plasmoids can read
  `~/.config/plasma-org.kde.plasma.desktop-appletsrc` (XHR on file://)
  but cannot write files. Profiles store the captured text as JSON in
  the plasmoid configuration; apply builds a backup, write and
  plasmashell restart command list, executed through the executable
  dataengine when the host Plasma still provides it (probed at
  runtime, with an honest explanation when absent).

## Bundle AppImage

Desktop shells load widgets from fixed user directories, so the AppImage
is a manager, not a runtime. It bundles every variant, detects the
desktop (XDG_CURRENT_DESKTOP, then XDG_SESSION_DESKTOP, then shell
binaries on PATH) and the OS pretty name, and lists only the matching
widgets. The GTK window (python3-gi) can install or uninstall files,
add or remove instances on the panel or the desktop, and update the
AppImage itself from GitHub Releases. CLI actions still work: `install`,
`uninstall`, `status`, `add-instance`, `remove-instance`, `update-check`,
`update`, plus `--only`, `--dry-run` and `--list`. Everything is HOME
scoped.

Each widget has a `surface` in `payload/manifest.json`: clocks and the
workspace grid default to the desktop, workspace names, command launcher
and panel profiles default to the panel. KDE still ships one plasmoid
per family; surface is only the default placement.

Build: `python3 dev-tools/ports-release.py bundle` builds every
unblocked port, stages the Cinnamon payload, assembles the AppDir and
runs appimagetool (downloaded once into `dev-tools/cache/`, or pass
`--appimagetool`). Bundle version lives in `dev-tools/appimage/VERSION`.
The payload manifest (`payload/manifest.json`) is the single source of
truth for what installs where and how each desktop enables it.

Published AppImage releases live on
`CurbSoftware/curb-desktop-widgets`.

## Standalone port repos

Users who want one widget, not the bundle, get a generated GitHub repo
per GNOME extension and per Plasma plasmoid. Layout is the installable
tree (zip/tarball contents at repo root) plus README and LICENSE. They
live under `~/projects/cinnamon/ports/` (sibling of the Cinnamon
`xlets/` clones), not inside this monorepo.

```bash
./dev-tools/publish-ports.sh --dry-run
./dev-tools/publish-ports.sh
```

Repo names: `gnome-world-clock`, `kde-world-clock`, and the same pattern
for the other families, plus `curb-desktop-widgets` for the AppImage.
Command Launcher is published here; the Spices block is Cinnamon-only.


## Testing rules

- Pure logic lives in `lib/` and is tested headless: `gjs -m` for GNOME
  ESM, `node` for KDE plain JS, `python3` for the tz table against
  zoneinfo ground truth.
- Widget code is verified by the live checklist in each tree's
  `DEVELOPMENT.md`.
- Every tree's tests are wired into the `PORTS` table from day one.
- Version discipline matches Cinnamon: bump `metadata.json` `version`
  (GNOME) or `KPlugin.Version` (KDE) on every functional change.
- No em-dashes, no emojis, in any file. `ports-release.py check` gates it.
